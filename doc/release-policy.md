# 两个启动器的配套发布

用户于 2026-11-11 要求 ThinkRail Launcher Lite 按 Antigravity Launcher Lite 的版本与发布流程维护，以后两个项目一起发布。

## 版本与授权

- 本次 ThinkRail 首个公开安装包对齐 Antigravity 当前的 1.0.2。此前准备的 0.1.1 未公开发布，不作为正式发布版本保留。
- Antigravity 1.0.2 已于 2026-11-09 发布，本次不覆盖其标签或附件。后续两个项目使用同一递增版本号，例如下批为 1.0.3。
- 此后用户要求发布任一项目，默认同时准备并发布两个项目；仅有代码修改不代表要求发布。用户明确指定只发布一个项目时遵从该次指令。
- 两仓库保持独立：应用标识、客户端身份校验、配置目录、更新端点和签名密钥不混用。基础功能是否需要同步，应在准备发布时逐项核对，不能把版本号相同当成功能已经相同。

## 每批操作

1. 核对两个仓库工作区、远程 main、现有 Release 和版本，避免混入其他未完成修改或覆盖已有公开版本。
2. 同步两项目的 npm/Tauri/Cargo 及锁文件版本，分别填写发布说明和真实验证范围。
3. 两项目分别完成本地检查和三平台常规 CI。维护者用已授权账号创建/核对两个版本草稿，targetCommitish 分别固定为各自构建提交，再触发打包工作流；避免集成令牌新建草稿受限。原生打包均覆盖 macOS arm64/x64、Windows x64、Linux x64；生成 DMG/应用 ZIP、NSIS、deb/AppImage，并检查架构、签名完整性、安装包结构与 CI 启动。
4. 分别创建草稿并核对源码提交、附件集合、BUILD-METADATA 与 SHA256SUMS。接入 updater 的项目还需核对更新包签名与 `latest.json`，其签名绑定版本必须一致。
5. 两项目都通过后同批次公开为正式 Release 并设置 Latest。GitHub 两个仓库没有跨仓库原子发布操作；若中途失败，记录哪个已公开并重试未完成部分，不通过覆盖已发布附件伪造一致性。
6. 更新两个项目的发布记录。CI 编译、CI 安装/启动、真实平台交互和真实客户端对话验证分别记录。

当前 ThinkRail 已接入应用内更新，Antigravity 的已发布 1.0.2 尚无启动器自更新模块；版本对齐不会改变已有安装包内容。
